Closes the four data-layer performance Mediums (P-4, P-5, P-7, P-8) that Michael signed off as one danger-zone bundle. They are the same disease in four places: code that loaded EVERY photo and video into memory to do a job that needed almost none of them.

## What changed

- **P-5** — building a backup no longer copies the whole library's bytes into a fresh buffer before wrapping them in a Blob. `writeZip`/`buildFlog` now return `Uint8Array<ArrayBuffer>` so `new Blob([bytes])` takes them directly.
- **P-4** — `localLastModified` ("has anything changed?") walks a cursor reading only `updatedAt`, holding one record at a time, instead of loading every store plus every media blob.
- **P-7** — the photo-cleanup run loop is lifted out of the card into `src/ui/photoCleanupRun.ts` and now does what its own header comment always claimed: cursor the store for ids, then fetch and process one photo at a time.
- **P-8** — the restore and import stale-media passes read ids only, via `openKeyCursor`, instead of loading full records.

## Blast radius

Danger-zone files: `src/lib/db.ts`, `src/lib/flog.ts`, `src/lib/zip.ts`, and the new `src/ui/photoCleanupRun.ts`. No change to what a successful operation writes — every fix is about how much is held in memory while reading. The one write-path touch is P-7's rewrite-back, which is byte-identical in behaviour to the previous loop.
